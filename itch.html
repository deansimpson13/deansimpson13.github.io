Codeitch5-verilog-parser

ITCH is the binary feed NASDAQ uses to broadcast every order, cancel and trade. Trading firms parse it in FPGAs because hardware can decode a message in nanoseconds. I built a small version of that parser in Verilog, and spent most of my time checking that it decodes correctly.

Every message the hardware decodes gets compared field by field against a Python version. Both came from my reading of the spec, so they could share the same mistake. To catch that, I also ran an outside open-source parser on a slice of real NASDAQ data from January 2019. Over 500,000 real messages, the Verilog matched the Python model line for line, and the outside parser agreed on all 2.7 million fields.

I then synthesized it with free tools (Yosys and nextpnr) for a Lattice iCE40. The parser on its own takes 331 LUTs and 1,040 flip-flops, a small slice of the chip, and runs at about 91 MHz in the worst case. Shrinking one counter from 16 bits to 6 bits took that up from 81 MHz.

What testing caught
The decoder's buffer was one byte too short for the 40-byte F message. The Python comparison flagged it as soon as I added that type.
Limits
At one byte per clock it moves about 0.73 Gb/s, roughly 7% of 10 Gb Ethernet. Fine for testing, but far too slow for a live feed.
Next
Run it on a real FPGA board with ITCH bytes sent over UART, then build an order book on top of the decoded messages.
